# 编辑规则总表 v2.4

状态：已由项目负责人接受，作为 v2.4 生产规则生效。适用事件、专题与可能方向。

这是编辑决策的唯一规则入口。数值/枚举取自 [`governance/policy.json`](../../governance/policy.json)；字段结构见 [DATA-MODEL](../data/DATA-MODEL.md) 和 [REVIEW-CONTRACT](../data/REVIEW-CONTRACT.md)。执行步骤见 [WORKFLOW](WORKFLOW.md)。

## 0. 权威、适用范围与例外

**GOV-01 / MUST**：遵循本总表的语义、policy.json 的参数、数据契约的结构。其他页面只能补充所属模块的表达规范，不得降低证据/批准门槛。实现和文档冲突时停止该项发布，修复并增加回归测试；不能选一个有利版本继续发布。

**GOV-02 / MUST**：MUST 是门禁；SHOULD 可偏离，但 review.limitations 必须说明；MAY 是可选项。MUST 无临时口头豁免。改变门槛要修改政策版本、说明受影响案例、测试和负责人批准，不得静默调整参数迎合某个事件。

**GOV-03 / MUST**：历史豁免仅限 `legacy-baseline.json` 中内容指纹及其依赖均未变化的记录。它是技术债登记，不是合格证。禁止重新生成基线来消除错误。旧公开内容的删除、URL 变更及历史首次发布日期改写不属于常规更新；需单独迁移方案。未变化旧数据允许带警告构建，不自动重算评级。

**GOV-04 / MUST**：审批、来源访问、独立评审只能记录真实行为。程序只能验证记录结构、绑定与日期，不能验证“某人确实同意”或“摘录确实证明了主张”。AI 操作者不得写负责人姓名冒充人工复核。审批必须能回溯到明确的确认消息/工单。

## 1. 阶段合同

| 规则 | 阶段 | 必须输入 | 必须输出 | 不满足时 |
|---|---|---|---|---|
| RUN-01 | 建批次 | 范围、UTC 日期窗、代码基线、证据截止日、操作者/模型/提示词版本 | run；full / targeted / backfill | 未定范围停止 |
| DISC-01 | 发现 | 查询与日期窗 | 每通道状态、实际请求、结果数、留存件及哈希；六类覆盖 | 未覆盖记 partial/unavailable，不能伪称完整 |
| SCREEN-01 | 去重/初筛 | 原始候选和已发布事件索引 | 每个检查过的候选及五维评分理由；skip/pool/confirm 优先级 | 不因热度直接入库 |
| CONF-01 | 确认 | 待核候选 | fact/impact/analysis/controversy 四层结果、主张级摘录 | 核心事实未证实→hold |
| EDIT-01 | 编辑评估 | 冻结证据包 | new/update/merge；分类、阶段、日期、L 等级、影响输入、反例比较 | 重要判断不清→补证据或降低可支持上限，不猜 |
| REVIEW-01 | 复核 | 完整记录及原始证据 | 独立评审记录、异议处理、双语事实核对 | L2/L3 仅自审不通过 |
| PUB-01 | 批准/发布 | 通过门禁的精确记录版本 | 人工批准绑定 subject/review/policy 摘要；构建/路由/页面检查 | 无批准不得 published/push |
| FOLLOW-01 | 后续跟踪 | 新证据、纠错或到期任务 | 原 publishedAt 不变；updatedAt/changeLog；重新评估 | 不继承旧版本批准 |

“确认搜索已执行但没有找到”是合法结果；不能用“已完成”替代实际发现。事实、影响、分析和反方检索不能合并为一个来源列表。

### 发现覆盖的边界

**DISC-02 / MUST**：full 记录 policy 中全部核心通道及六类分类。`complete` 表示按所声明的采集协议覆盖了日期窗，并非穷尽互联网。HF 最新 20 条、HN 当前 top 30、搜索引擎首页、仅最新一期邮件都只能说明快照覆盖。无法分页或追溯时记 partial；空结果≠故障，必须保留请求成功和窗口范围的证据。

**DISC-03 / MUST**：partial/unavailable 要记录原因及重试结果（含“未重试及理由”）。not_applicable 只用于范围确实不适用，不用于掩盖故障。覆盖缺口不阻止已核实单个事件，但批次结论必须声明缺口，不能声称“无遗漏”。不同批次的发现召回率不与同证据评级一致率混算。

**DISC-04 / MUST**：发现原始结果可批量保存；所有实际进入人工/模型判断的候选均保留决定，包括 skip/hold。无需捏造被过滤的网页为候选，也无需为达到某种比例制造拒绝记录。标题不能证明点赞/转发量；指标缺失写未知。

### 初筛：只决定核实优先级

**SCREEN-02 / MUST**：五维均为 0/1/2 整数；未知取保守低值并记录原因。

| 字段 | 0 | 1 | 2 |
|---|---|---|---|
| verifiability | 找不到可定位事实材料 | 有可定位二手材料 | 有可定位原始材料 |
| novelty | 与已有同动作/同阶段重复 | 对已有节点有实质补充 | 独立的新动作/阶段 |
| spillover | 未见圈外影响材料 | 已指向一个明确受众 | 已指向至少两个不同受众；不能仅列想象用途 |
| durability | 仅热度或未知 | 存在具体后续行动/持续安排 | 已观察到后续采用或制度化，而非计划 |
| sourceQuality | 只有社区/来源不明 | 一个可靠独立来源或原始记录 | 原始材料加独立核实同一核心事实 |

总分 0–4→skip 优先级；5–7→pool；8–10→confirm。这里的 confirm 替代旧称 draft，**不是发布许可，不是 L 等级**。低分候选可以提前核实，但必须写 priorityOverrideReason；证据不足仍 hold。

## 2. 事件身份、日期和分类

**IDENT-01 / MUST**：先填 `seriesId + action + stage + dateBasis`，再定 new/update/merge。

- 同一动作/同一阶段的补充参数、反方、后续说明：update。
- 发布、预览、可用、部署、立法通过、生效、裁判、事故、披露、完成等阶段发生实质变化，且有独立日期与事实：可 new；必须说明与旧节点的区别，不能每次报道都新建。
- 同一系列但不同阶段不自动 new：没有新增权利/可用性/法律状态/已发生后果的仅 update。
- 两个节点重复描述同一动作：提出 merge 方案；合并涉及旧 URL 时先做迁移审核，不直接删除。
- 调查/起诉是程序事实，不等于认定违法；计划/签约不等于完成；可用不等于采用；开源公告不等于已开放权重。

**IDENT-02 / MUST**：日期取节点所述动作真实发生日；只知披露日就将节点定义为披露。保留 day/month/year 的证据精度，不制造 1 日。不再凭“普通人感知到的时刻”挑热度峰值。`evidenceCutoff` 是本轮可用证据截止日，允许后来的真实影响支持历史事件的回顾评级，不能伪称当年已经可知。

**CLASS-01 / MUST**：主分类按节点的核心动作，而不是评级或品牌：方法/能力→capability；产品可用性/使用方式→product；资本/所有权/市场结构→commerce；立法/监管/裁判→governance；事故/风险治理实践→safety；有证据的社会行为→society。法院动作即使源于事故仍主归 governance；事故节点主归 safety；融资不因为投向芯片变成 capability。

**CLASS-02 / MUST**：最多一个次分类，必须绑定一个不同于主分类核心事实的、独立成句且有来源的 claim。删去这个 claim 会丢失一个实际变化，才保留次分类。废止不可测的“30% 信息丢失”标准。多个合理主分类仍并列时：按节点标题动作选择；不能确定则在评审中解决，不能用数组顺序随机表达。

## 3. 证据链

**EVID-01 / MUST**：每个 claim 都绑定逐字摘录、定位信息、URL、实际访问日期、文本留存文件哈希和 claim-local originId。哈希证明本地文件未变，不证明网页真实性。保留必要上下文；不把搜索摘要作为已读全文。付费/失效/无权限记 blocked，优先找原始材料或可靠存档，不能填造摘录。

**EVID-02 / MUST**：Tier 评价来源性质；A–D 评价这条主张的证明力度。publisherId 对同控制主体去重；originId 对同原始信息起源去重。转载同一公司新闻稿、两个媒体复述同一厂商跑分，不是两次验证。来源默认 originId 可记录整篇主要起源，摘录级 originId 用于混合来源稿件。关系分 primary/independent/interested/unknown，验证分 direct/independent_verification/reported/context。

**EVID-03 / MUST**：证据等级上限：

- A：原始直接材料＋不同起源/控制主体的独立验证；或至少两组独立验证。仅“报道了有该公告”不验证性能。
- B：可靠 Tier 1 直接支持；或两个不同起源、不同控制主体的独立 Tier 2。
- C：可靠单一独立二手支持；不能升级为已经独立复现。
- D：只有传闻、未核实营销、百科背景或未知链条。不能支撑公开事实/影响。

百科可用于背景，不独立满足发布证据门槛。厂商公告可以直接证明“厂商宣称 X”，不能直接证明“X 性能优于 Y”。每条核心事实至少 B。L2 还必须满足对应变化路径；缺一手材料时须说明原因，核心事实仍需两个独立 Tier 2。L3 必须有原始材料及规定数量的独立起源，核心转折不得依赖 C。

## 4. 历史重要度

**SIG-01 / MUST**：先确认事实，再评历史意义；不以融资额、厂商声量、新闻数量、模型参数或初筛总分直接指定 L2。L1 不代表“不重要”，只表示目前未证明符合更高等级。没有等级比例配额。

**SIG-02 / MUST**：依次检验相关路径；每项填写 true/false/数值/**null（未知）**、理由和证据。null 不等于反证；false 必须有支持该否定的材料。至少检查一个相关路径；不能为空列表规避判断。

| ruleId | 已发生的变化（所有条件 AND；不同路径 OR） | 独立验证对象 |
|---|---|---|
| L2-CAPABILITY | 明确此前不可行的任务、同条件基线、外部复测或可审计的独立任务裁判 | 任务结果；不要求从头重训模型，小幅榜单提分不自动算新任务 |
| L2-METHOD | 可复用的新方法/框架，规定数量的无关联后续工作实际采用 | 后续采用，不是纯引用计数 |
| L2-PRODUCT | 新工作流，规定数量的无关联组织在真实生产使用 | 实際使用，不是 logo、合作公告或试点意向 |
| L2-PRODUCT-ACCESS | 实质改变使用/再分发权限或可达性，规定数量的无关联生产采用 | 许可/可用性变化及采用；只是降价不自动成立 |
| L2-PRODUCT-SCALE | 新工作流，达到规定活跃用户数 | 注明 DAU/WAU/MAU、日期、估计方法；不以累计注册/下载替代 |
| L2-COMMERCE | 所有权、供需组织或交易规则的结构变化已执行，并影响规定数量的外部主体 | 交易两方外的已发生变化；融资/估值/产能规划本身不够 |
| L2-GOVERNANCE | 有约束力或先例效力的行为，适用超出具名当事人，有独立法律分析 | 适用范围/效力；一般提案、立案或索取资料不够 |
| L2-SAFETY | 有记录事故、外部实际补救行动、独立调查 | 调查发现；只有当事方自述报告不够 |
| L2-SAFETY-PRACTICE | 新安全实践，规定数量的无关联组织实际在生产采用 | 执行情况；承诺/评估框架发布不够 |
| L2-SOCIETY | 测得行为变化、规定数量独立人群及持续观察时长 | 行为与人群，不是搜索热度或短期话题 |

“新工作流”须描述旧流程→新流程，任务完成方式或参与者责任确实变化；“结构变化”须描述旧结构→新结构，而非只有规模增加。阈值的精确数字只维护在 policy.json。它们是**编辑政策，不是自然定律或预测实现标准**。

**SIG-03 / MUST**：L2 至少满足一个路径；L3 至少满足 policy 指定的不同类别数、观察期及独立起源数，并解释相互关联的跨领域持续变化。时间跨度长不等于持续观察；不能用“事件发生至今很多年”填观察期。否则最高可支持 L2。L3 不是 impactIndex 达到某个分数的别名。

**SIG-04 / MUST**：评审记录包括“已改变什么”“为何不是更低/更高”“至少两个已发布对照事件”。对照仅比较事实阶段、证据和变化类型，不照抄历史等级。旧证据包不足时输出“无法重评/待补证”，不能直接宣判降级。分歧不取平均：先比较证据截止日和未知项，再复核路径；解决不了则保留旧公开级别并阻止本轮评级变更。

## 5. 影响分、共识和争议

**IMP-01 / MUST**：影响只计已观察到的后果。尚未发生的潜在影响可以作为明确标注的 interpretation/open question，不进入影响指数。L1 尚无可核实影响时允许 impacts=[]、impactIndex=0；不为凑齐结构捏造影响。L2/L3 仍需影响条目和 impact claim。

**IMP-02 / MUST**：严重度按绝对值逐级检验：0=实测无方向性变化；1=有方向但未达到实质变化；2=证据支持工作流/权利/成本/风险暴露/行为等具体基线发生实质改变；3=满足 2 且达到政策规定受众广度与持续观察期。正负分别记录；风险的“存在”与损害的“发生”不能互换。记录 baseline/outcome/materialChange，严禁用情绪形容词代替。

**IMP-03 / MUST**：受众只用 policy 中互斥程度尽可能高的角色 ID；同一主体承担不同已证实角色才可重复跨组计入。developers 不得改写成 programmers/coders 分别加分。每个 impact 独立记录观察起止日；timeframe 由天数阈值计算，不由预测持续时间决定。0–29/30–179/180–364/365+ 天对应当前四档，精确值以配置为准。短期观察不得借长期预期拿耐久加分。

**IMP-04 / MUST**：保留 v2.3 公式及四舍五入方式，见 DATA-MODEL；不静默改写历史分数。它是影响量级摘要，不是概率、质量或有益程度；负向严重后果同样增加绝对影响。现公式理论最高舍入为 9（各项上限总和 9），0–10 是字段取值边界而非保证覆盖的量表；不得人工凑 10。

**CONS-01 / MUST**：emerging=主要影响证据仍积累；debated=存在有证据的规模/归因/解释分歧；broad=主要影响有至少两组独立支持且无未解决的实质反证。仅事实发布获得多家报道不能叫 broad。controversy 标记具体争议的存在，不是 emerging 的同义词；所有等级的 controversy=true 均需 limitation claim 和相应证据。

## 6. Arc、方向与语言

**ARC-01 / MUST**：Arc 只引用已发布事件，按 ARC-MODEL 的章节/时间跨度要求。章节论点是可辩论的编辑解释，不能新增未经核实事实；每个新增重要判断在 review 中留证据和反例。引用事件或来源变化时复核受影响章节；不得为了“有立场”编造因果。

**DIR-01 / MUST**：方向仍按 POSSIBLE-DIRECTIONS-SCREENING：至少两个公开事件、两个有事实锚点的 observed signals、独立来源与反向约束。run 中方向决定和 editorial.screeningRunId 必须连通。默认 monitor_only；外部共识证据不足时不能用事件评级的内部数值门槛宣布方向实现。

**LANG-01 / MUST**：中英文共享同一事实/主张台账，主体、数字、单位、日期、条件、否定、不确定性强度必须一致；任何语言都不享有“事实优先权”。可以从原始材料先写任一语言，也可以并行写作；不得为了自然表达增加事实。事件 summary 事实先行，Arc 可论点先行但必须有证据，方向区分当前基线与尚未成为常态的可能变化。

**LANG-02 / SHOULD**：句式、长度、修辞建议不是事实门禁。不得把某个“把/让/了”字或首句句法视为自动退稿理由；应检查主语、因果和证据是否清楚。语言人工复核与机械结构检查分开报告。

## 7. 完成标准与覆盖边界

- 规则完成：权威入口、阶段合同、含未知的评级分支、冲突处理、证据/审批/历史例外都有明确路径。
- 实现完成：正反例涵盖常规可发布、信息不足、证据来源混同、过期批准、错误引用、历史豁免绕过、影响重复计分及方向/Arc 边界。
- 校准完成：冻结案例与反事实样本，标注哪些是原有数据、哪些是测试构造；记录规则改动理由。**不等于旧事件已事实重审。**
- 跨模型验收：独立会话使用同一冻结证据、同一政策、同一提示词；对照 [CALIBRATION](CALIBRATION.md) 计算一致率、覆盖率和硬规则违规。未实测不得说已达标。

机械校验能查：字段/枚举/阈值/引用/日期/文件与摘要/证据上限/批准绑定。
机械校验不能查：摘录语义是否真的证明结论、组织是否真正无关联、是否完整发现候选、语言是否自然、人工批准是否真实、因果归因是否充分。上述 MUST 仍是评审职责，不因自动通过而免除。
