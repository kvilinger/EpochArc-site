# v2.4 体系优化：本地验收报告

范围：规则体系、模型/校验程序、正反例与已上线案例校准；本报告形成时未重评公开数据或处理外部待发布草稿。随后项目负责人已接受 v2.4 上线，并要求另行校验草稿。

## 1. 规范统一——已完成本地实现

- 新增唯一规则入口 EDITORIAL-STANDARD，按 MUST/SHOULD 区分门禁与建议。
- Discover → Screen → Confirm → Edit → Review → 人工批准 → Publish 的输入、输出、停止条件明确。
- 分开初筛优先级、历史重要度和可观察影响指数。
- 按类别定义 L2 路径、L3 的跨类别/实证持续性与独立起源条件；允许 null 表达未知。
- 分类按核心动作；次分类改为有证据的独立主张，不再使用 30% 信息丢失。
- 区分原始信息起源、控制主体、逐主张验证对象，避免把转载当独立验证。
- 双语统一为同一事实台账，消除“必须英文先写”与“中文禁止参考英文”的冲突；事件/Arc/方向各有表达边界。
- 同步 WORKFLOW、DATA-MODEL、REVIEW-CONTRACT、Skill、语言/风格、Arc、方向与上线清单。
- rulesDigest 绑定规则正文；policyDigest 绑定数值及正文摘要；变更后旧审核/批准不能自动复用。

规则与机器覆盖的逐项区别见 VALIDATION-COVERAGE。测试不证明来源真实、人工批准真实、文本自然或因果充分。

## 5. 尚未发生的事项

这不是“所有历史数据已按 v2.4 合格”，也不是“模型之间已达到 90% 一致率”。真实模型实验、已上线内容逐来源复核、评级迁移和发布均应另行启动。项目负责人已接受该政策。上线规范与校验器不自动改变历史评级；公开 Methods 的完整说明仍应在单独核对公开文案后同步。

数值阈值是可修订的编辑政策，不是经实证证明的自然分界线。今后的规则变更需说明反例、改版本、重跑冻结套件，而不是为单个事件加例外。
